# 代码规范建立

- **操作要求**
  - 扫描所有代码文件并按照规范进行修改
  - 所有规范都要记忆到CLAUDE.md
  - 清理所有无用的文件

# 后端规范

- **数据库操作**
  - 使用Sqlite数据库存储数据
  - 使用**实体命名**方式组织SQL语句
  - 支持环境变量方式进行数据库连接配置
    - **数据库连接命名**: DB_CONNECTION_STRING

- **日志记录**
  - 使用Serilog进行本地日志输出
  - 支持环境变量方式添加日志存储目录配置
    - **目录配置命名**: LOG_PATH

- **代码架构**
  - 项目使用模块化代码存储，所有业务代码都存储在Modules目录下
  - 严格按照**功能模块**/**功能分类**两个层级进行代码存储，每个层级都建立目录
  - 常量按照作用域，存储在对应的Constant目录下
  - 每个**功能分类**目录下定义Services、Apps、Entities等子目录并存储对应代码

- **命名规范**
  - 所有常量遵循大写下划线格式命名
  - 所有常量定义类命名以Const结尾
  - 所有Service类命名以Service结尾
  - 所有App类命名以App结尾

- **代码格式规范**
  - 使用Service类进行实际逻辑实现
  - 使用App类进行接口定义，并调用Service实现功能
  - 字符串要进行常量定义（路径，名称定义，特性定义除外）
  - if语句判断后的语句，必须用大括号进行包裹，只有一行代码也不能省略
  - 命名空间要与目录结构完全吻合
  - 所有代码必须兼容AOT编译

- **代码生成规范**
  - 严格按照项目规范进行代码生成，评估可行性，当现有技术规范不满足需求时，停止代码生成并提示
  - 只允许新增、修改、删除对话中明确要求操作的代码文件，其他文件只允许读取
  - 当代码生成后出现编译异常，需要评估需求合理性，如果需求不合理，则停止代码生成并提示
  - 对于对话中出现不合理的需求导致生成的代码无法编译或通过测试，应进行提示并先严格按照需求生成代码，不要随意变更需求
  - 除非对话中明确要求，其他情况一律不允许额外添加依赖包

- **注释规范**
  - 所有的public对象都需要使用///进行xml文档化注释
  - xml文档化注释中的param信息要匹配实际参数
  - 所有的private对象只需要使用//进行注释，减少代码篇幅
  - 注释/符号与注释内容之间留有一个空格

## 后端代码示例

- **实体命名**方式查询SQL
```
var todo = Todo.Named.Instance; // 数据表及字段命名
var r = Todo.Defined.Instance;  // C#类及属性定义名称
var t = new Todo.Named("t");    // 带表别名的数据表及字段命名
var sql = @$"
    SELECT 
        {t.Id} AS {r.Id},
        {t.Title} AS {r.Title},
        {t.DueBy} AS {r.DueBy},
        {t.IsComplete} AS {r.IsComplete}
    FROM {todo} {t}
";
```
