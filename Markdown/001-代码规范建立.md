# 代码规范建立

- **操作要求**
  - 扫描所有代码文件并按照规范进行修改
  - 所有规范都要记忆到CLAUDE.md
  - 严格执行规范要求，不进行额外的过度思考
  - 清理所有无用的文件

# 后端规范

- **数据库操作**
  - 使用Sqlite数据库存储数据
  - 支持环境变量方式进行数据库连接配置
    - **数据库连接命名**: DB_CONNECTION_STRING

- **日志记录**
  - 使用Serilog进行本地日志输出
  - 支持环境变量方式添加日志存储目录配置
    - **目录配置命名**: LOG_PATH

- **代码架构**
  - 项目使用模块化代码存储，所有业务代码都存储在Modules目录下
  - 严格按照**功能模块**/**功能分类**两个层级进行代码存储，每个层级都建立目录
  - 常量按照作用域，存储在对应的Constant目录下
  - 每个**功能分类**目录下定义Service/Controller子目录并存储对应代码
  - 每个**功能分类**目录下独立维护一个Entity代码文件，维护对应**功能分类**的**数据实体**定义
    - **Entity代码文件命名**: <功能分类>Entity.cs
    - **功能分类**下所有的实体对象都存储在同一个Entity代码文件中
    - 使用record关键字定义实体对象
    - 所有**数据实体**的JsonSerializable配置统一存储在AppJsonSerializerContext.cs中
  - 使用Minimal API标准进行Controller注册，并严格按照以下架构规范
    - 在**功能分类**目录下建立Router静态类，添加静态Register方法，方法中为**功能分类**下每个Controller进行路由注册
      - **功能分类Router命名**: <功能分类>Router.cs
    - 在**功能模块**目录下建立Router静态类，添加静态Register方法，方法中依次调用每个**功能分类**中的Router.Register针对全模块Controller进行路由注册
      - **功能模块Router命名**: <功能模块>Router.cs
    - **Controller注册流程**：Program.cs -> <功能模块>Router.Register -> <功能分类>Router.Register
    - **接口路由定义**
      - **规则**：/<功能模块>/<功能分类>/<功能>/<接口>
      - 使用小写字母加横杠方式命名
    - **接口路由定义示例**
      - **Todo.GetById接口**: /example/simple/todo/get-by-id

- **命名规范**
  - 所有常量遵循大写下划线格式命名
  - 所有常量定义类命名以Const结尾
  - 所有Service类命名以Service结尾
  - 所有Controller类命名以Controller结尾

- **代码格式规范**
  - 使用Service类进行实际逻辑实现
  - 使用Controller类进行接口定义，并调用Service实现功能
  - 字符串要进行常量定义（路径，名称定义，特性定义除外）
  - if语句判断后的语句，必须用大括号进行包裹，只有一行代码也不能省略
  - 命名空间要与目录结构完全吻合
  - 除非对话中明确要求，其他情况一律不允许额外添加依赖包
  - 对于对话中出现不合理的需求导致生成的代码无法编译或通过测试，应进行提示并先严格按照需求生成代码，不要随意变更需求
  - 项目需要进行AOT编译

- **注释规范**
  - 所有的public对象都需要使用///进行xml文档化注释
  - xml文档化注释中的param信息要匹配实际参数
  - 所有的private对象只需要使用//进行注释，减少代码篇幅
  - 注释/符号与注释内容之间留有一个空格
